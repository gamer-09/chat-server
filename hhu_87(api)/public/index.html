How to use the hhu_87 API Gateway

        
      

      

        
1. What this gateway does

        

          This server is an API Gateway. It receives requests and forwards them to other services
          ("downstream" servers). It also handles authentication and logs every request.
        


        
2. Environment variables

        
    
          
  • PORT – HTTP port for the gateway (default: 4008).
    • 
          
  • API_KEY – secret key required for all protected requests.
    • 
          
  • 
            SERVICE_<NAME>_URL – URL of a downstream service.
            Example: SERVICE_USERS_URL=http://localhost:5001 is used when you call
            /api/users/... through the gateway.
          
    • 
        


        
3. Gateway endpoints

        
    
          
  • GET / – JSON status and list of configured services.
    • 
          
  • GET /healthz – health check (no auth).
    • 
          
  • 
            /api/:serviceName/* – proxied routes.
            For example, /api/users/profile goes to the
            SERVICE_USERS_URL service at /profile.
          
    • 
        


        
4. Authentication

        

          All /api/... routes require your API_KEY. Send it as either:
        

        
    
          
  • Authorization: Bearer <API_KEY>
    • 
          
  • X-API-Key: <API_KEY>
    • 
        

        

          The /, /healthz, and /ui routes are public and do not
          require authentication.
        


        
5. Using this UI

        
    
          
  1. 
            In Authentication, paste your API_KEY and click
            "Save key locally". The key is stored in your browser only (localStorage).
          
    2. 
          
  2. 
            In Request Builder:
            
      
              
    • Select a Service (e.g. users).
      • 
              
    • Choose an HTTP Method (GET, POST, etc.).
      • 
              
    • Set the Path (e.g. /profile).
      • 
              
    • 
                Optionally provide a JSON Request body for methods like POST or PUT.
              
      • 
            
    
          
    3. 
          
  3. 
            Click Send request.
            The gateway sends /api/<service>/<path> with your API key and shows
            the response below.
          
    4. 
        


        
6. Example setup

        
PORT=4008
API_KEY=your-secret-key
SERVICE_USERS_URL=http://localhost:5001
SERVICE_ORDERS_URL=http://localhost:5002
        

        

          With this configuration you can, for example, request
          /api/users/profile through the gateway and it will be forwarded to
          http://localhost:5001/profile.
        

        
7. Extra gateway features

        
    
          
  • 
            CORS for browsers – controlled by CORS_ORIGIN. Use
            * to allow any origin, or set it to a specific frontend URL.
          
    • 
          
  • 
            Request IDs – you can send X-Request-Id on any request.
            If you omit it, the gateway generates an ID. The ID is returned in the
            X-Request-Id response header and appears in logs.
          
    • 
          
  • 
            Standard error responses – 401 for bad API key, 502 if a service
            is missing or fails, 404 when a route is not found, and 500 for unexpected errors.
            All error responses include a requestId field so you can match them to logs.
